# Тесты и проверка проекта

## Одна команда на всё

```powershell
powershell -File scripts\check-all.ps1      # или /sv-check в Claude Code
```

По очереди:

| Шаг | Что делает | Время |
|---|---|---|
| pytest | тесты backend на базе `secretvuln_test` | ~5,5 мин |
| build | `npm run build`: проверка типов (`src` и `e2e`) + сборка Vite | ~15 с |
| e2e | UI-тесты Playwright в настоящем браузере | ~1,5 мин |

В конце — таблица «прошло / упало», код выхода ≠ 0 при падении. Ключ `-Smoke` добавляет
`scripts\smoke-test.ps1` (ему нужны поднятые dev API, воркер и MinIO).

Docker Desktop должен быть запущен: скрипт сам поднимает Postgres и Redis.

## Как устроены UI-тесты

`scripts\e2e.ps1` поднимает **отдельный стенд** и гоняет на нём `playwright test`:

- база `secretvuln_e2e` — создаётся с нуля на каждый прогон;
- Redis — база `/1`, API — `:8001`, Vite — `:5174`, SARIF — `backend\data\sarif-e2e`, LDAP выключен.

Рабочая база и dev-стенд (`:8000`, `:5173`) не трогаются — их можно не останавливать.
После тестов процессы стенда гасятся всегда, даже при падении.

Тесты ведут себя как пользователь: входят, создают проекты, загружают SARIF, меняют статусы,
одобряют запросы — и проверяют, что на экране то, что нужно. Данные каждый тест готовит сам
через API (свои проекты и пользователи с уникальными именами), поэтому тесты не зависят друг от друга.

Что покрыто (`frontend/e2e/*.spec.ts`):

| Файл | Сценарий |
|---|---|
| `auth` | вход, неверный пароль, выход, редирект на вход без токена |
| `projects` | проект и дочерний, путь в дереве, наследование основной ветки |
| `import` | загрузка SARIF со страницы «Импорты», обработка воркером, повторная загрузка — только дубликаты |
| `finding` | окно SV-N: взять в работу, комментарий, история |
| `decisions` | «ложное» от разработчика → очередь «Запросы на одобрение» → одобрение админом |
| `access` | роль на поддерево: видно только его, чужое по прямой ссылке — «Не найдено» |
| `audit` | действия в журнале, раскрытие изменений, вкладка проекта «Журнал» |
| `pages` | все страницы без ошибок в консоли и сырых ключей i18n; переключение тем |

## Запуск по частям

```powershell
powershell -File scripts\e2e.ps1                          # все UI-тесты
powershell -File scripts\e2e.ps1 e2e/import.spec.ts       # один файл (аргументы уходят в playwright test)
cd backend; .\.venv\Scripts\python -m pytest              # только backend (/sv-test)
```

## Если упало

- На экране — хвост лога упавшего шага; полные логи — `backend\data\check-logs\`,
  логи API/воркера/Vite тестового стенда — `backend\data\e2e-logs\`.
- Упавший UI-тест оставляет трейс (каждый шаг, DOM, сеть) и скриншот:
  `cd frontend; npx playwright show-report`.
- Ретраев нет специально: нестабильный тест чинят, а не перезапускают.

## Как написать новый UI-тест

- Файл `frontend/e2e/<тема>.spec.ts`. Админ уже вошёл (`global-setup.ts` → `storageState`).
- Данные — через `Api` из `e2e/api.ts`: `createEntity`, `importSarif`, `projectWithFindings`, `grant`;
  пользователь без прав — `createUser()`, вкладка под ним — `pageAs()`. Имена — через `uniq()`.
- Тексты — только через `t()` / `tc()` из `e2e/i18n.ts` (строки из `ru.json`), не хардкодить русский.
- Селекторы — по ролям и подписям (`getByRole`, `getByLabel`). Нет подписи у поля — добавить её
  в компонент (`aria-label`, `htmlFor`), `data-testid` — только если иначе никак.
- Проверка «чего-то нет» (`toHaveCount(0)`) — только после того, как на странице появилось
  что-то из того же списка, иначе тест пройдёт на недогруженной странице.

## Окружение

- Браузер — установленный Google Chrome (`channel: "chrome"`); пустая `SV_E2E_CHANNEL` —
  встроенный Chromium Playwright (`npx playwright install chromium`).
- Учётки стенда — `frontend\e2e\.env.example`; свои — в `frontend\e2e\.env` (в `.gitignore`).
