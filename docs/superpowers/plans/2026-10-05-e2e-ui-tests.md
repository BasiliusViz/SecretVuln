# UI-тесты (Playwright) и проверка одной командой

Дата: 2026-10-05. Статус: утверждено направление (вариант «сквозные тесты в браузере»), делать в новой сессии.

## Цель

Одна команда — `powershell -File scripts\check-all.ps1` (и слэш-команда `/sv-check`) — проверяет весь проект
и печатает короткий итог «прошло / упало» по шагам:

1. backend: pytest (250 тестов);
2. frontend: `npm run build` (tsc + vite);
3. UI-тесты: Playwright в настоящем браузере через настоящие API, воркер и БД.

Smoke-скрипт (`scripts/smoke-test.ps1`) в общий прогон не входит: ему нужен MinIO, а импорт и так покрыт
pytest и UI-тестом импорта. Флаг `-Smoke` в `check-all.ps1` — по желанию.

## Решения

- **Изолированный стенд для UI-тестов, рабочую базу не трогаем.** Отдельная БД `secretvuln_e2e`
  (пересоздаётся на каждый прогон), Redis — база `/1`, API на `:8001`, Vite на `:5174`,
  хранилище — `local` в `backend/data/sarif-e2e`. Поэтому прогон можно запускать при поднятом dev-стенде.
- **Порт прокси Vite из env:** в `vite.config.ts` цель `/api` берётся из `SV_API_PROXY`
  (по умолчанию `http://localhost:8000`), порт — из `SV_WEB_PORT` (по умолчанию 5173).
- **Оркестрация — `scripts/e2e.ps1`:** пересоздать БД → `alembic upgrade head` → `create-admin`
  + `seed-roles` → запустить API, воркер, Vite в фоне (env `SV_*` на e2e) → дождаться `/health`
  и Vite → `npx playwright test` → остановить процессы (в `finally`, даже при падении).
- **Данные тесты создают сами** через API (хелпер в `frontend/e2e/api.ts`): проекты, группы, роли,
  пользователи с уникальными именами (`e2e-<timestamp>`). Логин админа — один раз в
  `global-setup` → `storageState`. Тестовые учётки — в `frontend/e2e/.env.example`, не в коде.
- **Только Chromium**, `workers: 1` (общая БД, процессы проще), ретраев нет — флак лечим, не прячем.
  Отчёт: `list` в консоль + HTML-отчёт в `frontend/playwright-report/` (в `.gitignore`).
- **Селекторы — по ролям и тексту** (`getByRole`, `getByLabel`), текст сверяем со строками из
  `i18n/ru.json` (импорт JSON в тесты), а не с захардкоженным русским. `data-testid` — только где без него никак.

## Сценарии (по файлу на тему, `frontend/e2e/*.spec.ts`)

| Файл | Что проверяет |
|---|---|
| `auth.spec.ts` | вход, неверный пароль, выход, редирект на логин без токена |
| `projects.spec.ts` | создать проект и дочерний, путь в дереве, настройки наследуются |
| `import.spec.ts` | загрузка `scripts/samples/semgrep.sarif` через страницу «Импорты» → обработка воркером → уязвимости в списке; повторная загрузка не плодит дубли |
| `finding.spec.ts` | окно `SV-N`: смена статуса, событие в истории |
| `decisions.spec.ts` | запрос «ложное срабатывание» → одобрение во «Входящих» → статус уязвимости |
| `access.spec.ts` | пользователь с привязкой к поддереву видит только его; чужой проект по прямой ссылке — «не найдено» |
| `audit.spec.ts` | действия из тестов видны в журнале, раскрытие изменений |
| `pages.spec.ts` | каждая страница из `App.tsx` открывается без ошибок в консоли и без сырых ключей i18n; переключение тем |

## Задачи

1. Playwright в `frontend` (devDependency `@playwright/test`, `npx playwright install chromium`), `playwright.config.ts`, скрипт `npm run e2e` — `frontend/package.json`, `frontend/playwright.config.ts`, `.gitignore`.
2. Порты/прокси Vite из env — `frontend/vite.config.ts`.
3. Оркестратор стенда — `scripts/e2e.ps1` (без BOM-проблем: см. грабли в скилле `secretvuln-dev`).
4. Хелперы: `global-setup.ts` (логин → storageState), `e2e/api.ts` (создание данных через API), `e2e/i18n.ts` — `frontend/e2e/`.
5. Сценарии из таблицы — по одному файлу, гонять каждый сразу после написания.
6. Общий прогон — `scripts/check-all.ps1` (pytest → build → e2e, итоговая таблица, код выхода ≠ 0 при падении) и `.claude/commands/sv-check.md`.
7. Документация: раздел «Тесты» в скилле `secretvuln-dev`, строки в карте файлов `CLAUDE.md`.
8. Ревью `sv-reviewer` по диффу, прогон `check-all.ps1` дважды подряд (проверка на флаки и на чистое пересоздание БД).

## Готово, когда

- `scripts\check-all.ps1` проходит с нуля дважды подряд при поднятом dev-стенде, dev-база не меняется;
- упавший UI-тест оставляет трейс/скриншот в отчёте; процессы стенда не остаются висеть.
