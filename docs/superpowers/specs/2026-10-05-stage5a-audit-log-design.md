# Этап 5а: аудит-лог и `uploaded_by` у импортов

## Зачем

Ответить на вопросы «кто выдал доступ», «кто поменял настройки/SLA/роль», «кто входил и были ли неудачные попытки», «кто загрузил этот импорт». История уязвимостей уже есть в `finding_events` — её не дублируем.

## Объём

**Пишем в журнал (вариант A):** вход (успех/неудача), проекты (создание, правка, перенос, удаление, создание по пути при импорте), настройки проекта и правила владельцев, переназначение, группы и состав групп (включая LDAP-синхронизацию), роли и их права, привязки (на проект и глобальные), SLA-политики, импорты.

**Не пишем:** действия над уязвимостями и решениями (`finding_events`), чтение.

**Вне этапа:** ротация/очистка, экспорт в SIEM, неизменяемость на уровне БД, CI-токены и сервисные учётки.

## Модель `audit_log` (миграция 0015)

| Поле | Тип / смысл |
|---|---|
| `id` | UUID PK |
| `created_at` | `server_default=clock_timestamp()` — не `now()`, чтобы записи одной транзакции были упорядочены |
| `actor_type` | enum `user` / `system` |
| `actor_id` | FK users, `SET NULL` |
| `actor_label` | снимок email; при неудачном входе — введённый логин, обрезанный до 255 |
| `action` | строка `<объект>.<действие>`, константы в `services/audit.py` |
| `target_type`, `target_id`, `target_label` | объект действия и снимок его имени/пути |
| `entity_id` | FK entities, `SET NULL`; `NULL` = глобальное событие |
| `entity_path` | снимок пути, только для показа |
| `changes` | JSONB `{поле: [было, стало]}`; для create/delete — ключевые поля |
| `ip` | `request.client.host` |

Индексы: `(created_at)`, `(entity_id, created_at)`, `(actor_id, created_at)`. Только вставка, без `updated_at`.

### Правила

- **`entity_id`**: событие над проектом/его настройками/привязкой на проект → этот проект; **`entity.delete` → родитель** (у корня `NULL`), чтобы удаление видел руководитель поддерева. Роли, группы, вход, SLA-политики, глобальные привязки → `NULL`.
- **Секреты**: в `changes` только поля из явного белого списка на тип объекта; пароли, `hashed_password`, токены не пишутся никогда.
- **Неудачный вход**: запись коммитится явно до `raise HTTPException(401)`.
- **LDAP-синхронизация групп**: `group.member_add/remove` с `actor_type=system` только при реальном изменении состава.
- **IP за прокси**: заголовки сами не разбираем; в проде uvicorn с `--proxy-headers --forwarded-allow-ips`.
- **Перенос проекта**: видимость считается по текущему пути через `entity_id` — события едут вместе с проектом.
- **Удалённый проект**: `entity_id` становится `NULL`, события видны только глобальным аудиторам; путь остаётся в `entity_path`.

## Запись

`services/audit.py`: `record_audit(db, actor, action, *, target=None, entity=None, changes=None, ip=None)` — добавляет строку в текущую сессию (коммит вместе с действием); `diff(before, after, fields)` — «было/стало» по белому списку. Вызывается **только в слое API** (там `principal` и `request`).

## Права

- `audit:read` в `CATALOG`, на поддерево (не `GLOBAL_ONLY`).
- Видимость: `entity_id` в `access.entity_scope("audit:read", AuditLog.entity_id)` **или** (`entity_id IS NULL` и `access.is_global("audit:read")`). Суперпользователь — всё.
- Встроенные роли: Аудитор, Руководитель команды, Администратор.

## API

`GET /api/v1/audit` (гейт `require_permission("audit:read")`), фильтры: `entity_id` + `subtree` (по умолчанию true; невидимый проект → 404), `actor` (ilike по `actor_label`), `action` (точно или префикс `binding.`), `target_type` + `target_id`, `date_from`, `date_to`, `limit`/`offset`. Ответ `{items, total}`, сортировка `created_at DESC`.

**`uploaded_by`**: в `ImportRead` поле `uploaded_by: {id, email, display_name} | null` (`selectinload`); в списке импортов фильтр `uploaded_by=me`.

## UI

- **Импорты**: колонка «Загрузил» («—», если `null`), переключатель «Только мои».
- **Журнал аудита** `/audit`, пункт сайдбара `perm: "audit:read"`: колонки Время / Кто / Действие / Объект / Проект / IP; действие — `t("audit.action.<action>")`, неизвестное — сырая строка; раскрытие строки — таблица изменений «Поле / Было / Стало»; фильтры: период, кто, действие (группы: Вход, Проекты, Доступ, Группы, Роли, SLA, Импорты), проект; пагинация.
- **Вкладка «Журнал»** в настройках проекта при `can("audit:read", path)` — тот же компонент с фиксированным `entity_id`, `subtree=true`.

## Тесты

- **Сторож**: для каждого POST/PUT/PATCH/DELETE в `app.routes` исходник эндпоинта содержит `record_audit(` либо роут в `EXEMPT` с причиной (уязвимости/решения → `finding_events`, `metrics/aggregate` — чтение).
- Запись по ключевым действиям: привязка, роль, проект, вход ok/fail, импорт.
- Видимость: аудитор на `a` не видит `b` и глобальные; глобальный видит всё; `entity.delete` виден правам на родителя.
- `changes` без секретов; `uploaded_by` в ответе и фильтр `me`.
