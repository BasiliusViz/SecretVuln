# Этап 6 «Дашборд-виджеты» — спека

> **ОТЛОЖЕНО (2026-10-05).** Решили не делать: «Обзор» уже собирается из JSON-конфигов на фронтенде поверх generic `/metrics/aggregate` (этап 3), запросов на личные дашборды нет. Вернуться, если пользователи попросят. Аудит виджетов в любом случае не нужен (личная настройка, как в Jira/Grafana).

Личный дашборд: пользователь сам собирает виджеты из generic-агрегатов. Данные — существующий `POST /metrics/aggregate` (этап 3), новых эндпоинтов данных нет.

## Что храним

Таблица `dashboard_widgets` (миграция `0016`):

| Поле | Тип | Смысл |
|---|---|---|
| `id`, `created_at`, `updated_at` | миксины | |
| `user_id` | FK `users` ON DELETE CASCADE, index | владелец (дашборд личный) |
| `title` | `String(200)`, nullable | своё название; пусто — UI строит из конфига |
| `config` | JSONB | `{chart_type, metric, group_by, period, filters}` |
| `position` | int | порядок на дашборде |
| `width` | enum `half` / `full` | ширина в сетке |

`config` валидируется схемой `WidgetConfig = MetricQuery + chart_type` (`extra: forbid`, только белые списки). `chart_type`: `number`, `bar`, `hbar`, `line`, `pie`, `table`. Совместимость `chart_type` ↔ `group_by` (например `line` только с `week`, `number` только с `none`) проверяет бэкенд → 422.

Лимит — 30 виджетов на пользователя.

## Generic-агрегат (расширение `services/metrics.py`)

- `group_by` += `status`, `rule_id`, `cwe` (колонки Finding, белый список `GROUP_COLUMN`).
- Метрика `total` — все находки любого статуса (срез), чтобы «по статусам» тоже стало виджетом.
- Фильтр `filters.status: list[FindingStatus]` — применим к любой метрике (сужает, не расширяет: для `count` открытые ∩ выбранные).
- Видимость как сейчас: `scope=readable(principal)` → только доступные поддеревья; `filters.entity_id` вне видимости → 404.

## API

Все под `/api/v1/dashboard/widgets`, ворота `finding:read` (без него дашборд пуст и бесполезен). Новых прав в каталоге нет: виджет — личная настройка, работает только владелец. Чужой виджет → 404, даже для суперпользователя (не админская сущность).

- `GET` — свои виджеты по `position`.
- `POST` — создать (в конец). `filters.entity_id` должен быть видим вызывающему, иначе 404.
- `PATCH /{id}` — `title`, `config`, `width`.
- `DELETE /{id}`.
- `PUT /order` — `{ids: [...]}`: полный список своих id в новом порядке (не тот набор → 422).
- `POST /defaults` — создать стандартный набор (если виджетов нет; иначе 409). Набор — константа `DEFAULT_WIDGETS` в `services/dashboard.py`: открытые по критичности, открытые/закрытые по неделям, просрочено по командам, MTTR, доля в SLA.

Если доступ к `filters.entity_id` потерян после сохранения — виджет остаётся, `/metrics/aggregate` отдаёт 404, UI показывает «нет доступа к проекту».

## Аудит

`record_audit` на каждой мутации: `dashboard_widget.create/update/delete/reorder/defaults`. Событие глобальное (`entity_id = NULL`, видно только глобальному `audit:read`), `changes` по белому списку `FIELDS` (`title`, `config`, `width`). `test_audit_coverage` и `test_route_coverage` — классифицировать новые маршруты.

## UI (сессия 2)

- «Обзор» (`/`): сверху — плитки (`number`), ниже сетка своих виджетов; пусто → кнопка «Стандартный набор».
- Конструктор (модалка): метрика → группировка (только совместимые) → тип графика → период → фильтры (критичность, сканер, статус, проект, тег) → живой предпросмотр через `/metrics/aggregate`.
- Меню виджета: изменить, ширина, вверх/вниз, удалить. Recharts, цвета из темы (`useSeverityColors`), все строки — `ru.json`.
- Нынешние жёстко заданные блоки «Обзора» уходят в `DEFAULT_WIDGETS`.

## Не делаем

Общие/командные дашборды, drag-and-drop, экспорт, свои SQL/поля вне белого списка.
