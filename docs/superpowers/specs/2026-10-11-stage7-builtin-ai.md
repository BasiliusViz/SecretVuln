# Этап 7 «Встроенный ИИ» — спека

Дата: 2026-10-11. Основа: `2026-10-10-stage6-ai-agent-output.md` (раздел «Новый порядок этапов»).

## Решения (обсуждение 11.10.2026)

- **Провайдер = протокол**: один клиент OpenAI-совместимого `/v1/chat/completions` (Ollama, vLLM, шлюз LOCAL-AI, облако). Без SDK, на `httpx`.
- **Под конкретную модель не привязываемся**: в `.env.example` модель пустая, промпты общие, в тестах — заглушка. Проверка на живой модели — отдельным шагом, когда она будет.
- **Запуск**: автоматически после импорта (новые находки основной ветки, с лимитом) + кнопка «Разобрать ИИ».
- **Согласие**: явное (принято/отклонено у вывода) + неявное (итоговый статус находки).

## Настройки (env)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SV_AI_BASE_URL` | пусто | Адрес `/v1`. Пусто — встроенный ИИ выключен |
| `SV_AI_API_KEY` | пусто | Bearer-ключ (шлюз, облако) |
| `SV_AI_MODEL` | пусто | Имя модели |
| `SV_AI_TIMEOUT` | 60 | Таймаут запроса, секунды |
| `SV_AI_AUTO_LIMIT` | 50 | Сколько новых находок одного импорта разбирать автоматически; 0 — автозапуск выключен |

## Бэкенд

- **Клиент** `services/llm/client.py`: `chat_json(messages, schema)` → POST `/chat/completions` с `response_format: {"type": "json_object"}`; вырезает `<think>…</think>`; валидирует Pydantic-схемой; при невалидном ответе — один повтор, затем `LlmError`. Сетевые ошибки и не-2xx — тоже `LlmError`.
- **Промпт** `services/llm/prompts.py`, `PROMPT_VERSION = "triage-v1"`. Один вызов на находку, ответ:
  `{title_plain, explanation, remediation, verdict: true_positive|false_positive|uncertain, confidence: 0..1, reasoning}`.
  Вход: правило (id, имя, описание), сообщение, сканер, severity, CWE, файл и строка, фрагмент кода из `raw` (обрезка по длине). **Для находок-секретов фрагмент не передаётся** (маскирование — этап 8). Тексты ответа — на русском.
- **Триажёр** `services/builtin_triage.py`: `triage_finding(db, finding_id)` — собрать вход, вызвать модель, записать две строки `ai_analyses` (`summary` и `triage`), `agent="sv-builtin"`, `model=SV_AI_MODEL`, `prompt_version`, `created_by=NULL`; вердикт находки обновляет существующий `refresh_ai_verdict`.
- **Воркер**: задача `ai_triage_finding(finding_id)`, `_job_id = "ai:{finding_id}"`. В конце `process_import`, если ИИ включён и импорт из основной ветки, — ставим в очередь новые находки (до `SV_AI_AUTO_LIMIT`), пропуская находки, у которых уже есть вывод `sv-builtin`. Ошибка модели — в лог, импорт не падает, строк не пишем.
- **API**:
  - `POST /api/v1/findings/{id}/ai-triage` → 202; право `finding:analyze`; невидимая находка → 404; ИИ выключен → 503. Ставит в очередь всегда (повторный разбор). Пишет аудит.
  - `GET /api/v1/ai/status` → `{enabled, model}` (любой вошедший пользователь).
- **Метрика `ai_agreement`** в `POST /metrics/aggregate`: по выводам `kind=triage` с вердиктом `true_positive`/`false_positive` (`uncertain` не учитывается), период — по `created_at` вывода.
  - Явное: `review_status=accepted` → согласие, `rejected` → несогласие.
  - Неявное (если `pending`): статус находки `false_positive` → согласие при вердикте `false_positive`; `confirmed`/`in_progress`/`fixed`/`risk_accepted` → согласие при `true_positive`; `new`/`triaged` — не учитываются.
  - Значение — процент согласия; `count` — число учтённых выводов. Новые разрезы `ai_agent`, `ai_model` (вместе с существующими).

## Фронтенд (отдельная сессия)

- Блок «Анализ ИИ»: кнопка «Разобрать ИИ» (если `enabled` и есть право), после нажатия — «В очереди».
- Дашборд: плитка «Согласие с ИИ».
- Строки — в `ru.json`.

## Тесты

- pytest: клиент через `httpx.MockTransport` (разбор, `<think>`, повтор при битом JSON, ошибки), триажёр (две строки, секреты без фрагмента), автозапуск (лимит, только основная ветка, пропуск разобранных, выключено при пустом URL), эндпоинт (202/404/503/права), метрика согласия (явное, неявное, `uncertain` и открытые не считаются).
- e2e: при выключенном ИИ кнопки нет.
