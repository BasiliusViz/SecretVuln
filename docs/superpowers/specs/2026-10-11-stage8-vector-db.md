# Этап 8 «Векторная база» — спека

Дата: 2026-10-11. Основа: `2026-10-10-stage6-ai-agent-output.md` (порядок этапов), `2026-10-11-stage7-builtin-ai.md`, исследование `docs/proposals/2026-09-19-ai-knowledge-hub.md` (L2, §6).

## Решения (обсуждение 11.10.2026)

- **Объём**: «Похожие находки» в окне SV-N, `find_similar` в MCP и поиск по смыслу для агентов (`query` в `search_findings`). Поиска по смыслу в таблице UI на этапе нет.
- **Хранение**: pgvector в своём Postgres, колонка фиксированной размерности `vector(1024)` (под `bge-m3`). Смена модели той же размерности — автоматическая переиндексация; другой размерности — новая миграция.
- **Триажёр получает похожие**: до 3 решённых человеком находок из того же корневого проекта в промпте (`triage-v2`), их id — в выводе.
- **Протокол**: OpenAI-совместимый `/v1/embeddings` (Ollama, vLLM, шлюз), без привязки к конкретной модели; в тестах — заглушка.

## Настройки (env)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `SV_AI_EMBED_MODEL` | пусто | Модель эмбеддингов. Пусто — векторы и «Похожие» выключены |
| `SV_AI_EMBED_BASE_URL` | пусто → `SV_AI_BASE_URL` | Отдельный адрес `/v1` для эмбеддингов |
| `SV_AI_EMBED_DIM` | 1024 | Ожидаемая размерность; должна совпадать с колонкой |

Векторы включены, если задана модель и есть адрес (свой или общий). Ключ — общий `SV_AI_API_KEY`.

## Данные

- Образ Postgres — `pgvector/pgvector:pg16` (pgvector ≥ 0.8) в docker-compose, тестах и стенде e2e. Миграция: `CREATE EXTENSION IF NOT EXISTS vector`.
- `finding_embeddings`: `finding_id` (PK, FK → findings, cascade), `model`, `content_hash` (sha256 канонического текста + имени модели), `embedding vector(1024)`, `created_at`. Индекс HNSW `vector_cosine_ops`.
- `ai_analyses.similar_ids` — JSONB, список UUID находок, на которые опирался вывод (по умолчанию `[]`).
- Python-пакет `pgvector` (тип для SQLAlchemy).

## Бэкенд

- **Маскирование** `services/masking.py` (общее для эмбеддингов и LLM):
  - `is_secret_finding` переезжает сюда из `llm/prompts.py`. Для секретов в текст идут только сканер, правило, CWE и путь — без сообщения и кода.
  - `mask(text)` для остальных: известные префиксы (`AKIA…`, `ghp_`/`github_pat_`, `sv_…`, `xox?-`, `sk-…`, JWT, `-----BEGIN … PRIVATE KEY-----`), присваивания `password|passwd|secret|token|api_key… = / :` значение, высокоэнтропийные строки (≥ 20 символов, энтропия Шеннона ≥ 4.0) → `[MASKED]`.
  - Подключается и в промпт триажёра (закрывает «маскирование — этап 8» из спеки этапа 7).
- **Клиент** `services/llm/client.py`: `embed(texts) -> list[list[float]]` — POST `/embeddings`, проверка числа векторов и размерности (`SV_AI_EMBED_DIM`), ошибки → `LlmError`. Фабрика `get_embed_client()`.
- **Канонический текст** `services/embeddings.py`: сканер, rule_id, имя правила, CWE, сообщение, путь, фрагмент кода (обрезка до ~2000 символов), всё через маскирование.
  - `embed_pending(db, limit=500)`: находки без вектора или с другим `content_hash` (изменился текст или модель) → пачками по 32 → upsert. Возвращает число обработанных.
  - `ensure_embedding(db, finding)`: посчитать вектор одной находки сразу (для триажёра).
- **Воркер**: задача `embed_pending` с `_job_id="embed"`, `keep_result=0` (не идут две одновременно); ставится в конце `process_import` и cron раз в час (дочищает сбои и переиндексирует при смене модели). Ошибка модели — в лог, импорт не падает.
- **Похожие** `services/similarity.py`:
  - `find_similar(db, principal, finding_id, limit=5)`: косинусная близость; исключаются сама находка и находки с тем же `fingerprint`; **фильтр видимости `Access`** (тот же, что в списке находок); в транзакции `SET LOCAL hnsw.iterative_scan = relaxed_order`, чтобы фильтр прав не обрезал выдачу индекса. Нет вектора — `{"pending": true, "items": []}`.
  - Каждый элемент: id, номер, заголовок, путь проекта, статус, severity, `similarity` (0..1), `decision` — последний переход статуса, сделанный человеком (`finding_events`, `actor_type=user`): статус, `reason`, `reason_tag`, дата.
  - `search_by_text(db, principal, query, **filters)`: вектор запроса (маскируется) + фильтры `findings_query`, сортировка по близости.
- **Триажёр** `triage-v2`: перед вызовом — `ensure_embedding`; до 3 похожих в статусах `false_positive`/`confirmed`/`risk_accepted` с решением человека, **только из того же корневого проекта**; в промпт — внутри той же границы недоверенных данных, замаскированные; id — в `similar_ids` обеих строк. Векторы выключены или ошибка эмбеддинга — разбор без похожих.
- **API**:
  - `GET /api/v1/findings/{id}/similar?limit=5` (1..20): право `finding:read`; невидимая находка → 404; векторы выключены → 503.
  - `GET /api/v1/ai/status` → добавить `embeddings_enabled`.
  - `similar_ids` — в схеме вывода ИИ.
- **MCP**: инструмент `find_similar(ref, k=5)`; в `search_findings` необязательный `query` (поиск по смыслу). Векторы выключены и передан `query` — понятная ошибка. Ответы — с `UNTRUSTED_NOTICE`.

## Фронтенд (отдельная сессия)

- Окно SV-N, блок «Похожие находки» (если `embeddings_enabled`): до 5 строк — ссылка SV-N, заголовок, проект, статус, решение с причиной, процент похожести. `pending` — «Похожие ещё вычисляются». Пусто — «Похожих не найдено».
- Блок «Анализ ИИ»: «На основе похожих: SV-12, SV-40» (если `similar_ids` не пуст).
- Строки — в `ru.json`.

## Тесты

- pytest (векторы — детерминированная заглушка клиента):
  - маскирование: префиксы, присваивания, энтропия, обычный код не трогается, секреты без сообщения;
  - `embed` через `httpx.MockTransport`: пачки, неверная размерность и число векторов → `LlmError`;
  - `embed_pending`: только новые и изменённые, переиндексация при смене модели, выключено без модели;
  - похожие: порядок по близости, **находки чужого проекта не видны**, дубли по fingerprint исключены, `decision` от человека, `pending`;
  - эндпоинт 200/404/503/права; MCP `find_similar` и `search_findings(query)`;
  - триажёр v2: только решённые, только тот же корень, `similar_ids`, маскирование в промпте, работа без векторов.
- e2e: при выключенных векторах блока «Похожие находки» нет. Проверка с включёнными — только если заглушка `/v1/embeddings` на стенде окажется дешёвой.
