# Новый вид дашборда (образец — shadcn dashboard-01)

Дата: 2026-11-14. Статус: вид согласован по макету в чате, код сделан 14.11 (не закоммичен): сборка и `e2e/pages.spec.ts` зелёные, проверено в пяти темах и на ширине 900px. Итог проверки API: фильтр по проекту с поддеревом и последние находки (`order=number`) уже были; сдвинутого периода нет — плашек у «Среднего времени» и «Согласия с ИИ» нет. Не сделано: переходов из «По критичности» в список не было и нет (страница «Уязвимости» не читает фильтр из адреса); на ширине телефона сайдбар не сворачивается и сжимает страницу — это общее для всех страниц, в задачу не входило. Полный `/sv-check` и ревью не запускались.

## Решение

- Образец: <https://ui.shadcn.com/view/new-york-v4/dashboard-01> — только раскладка и вид карточек.
  Код оттуда не берём: в проекте нет Tailwind и shadcn, и не добавляем.
- Цвета — только существующие переменные тем (`--bg-card`, `--border`, `--accent`, `--sev-*`…).
  Новая тема не нужна, вид должен работать во всех пяти.
- Меняется только страница `Dashboard`. Сайдбар, остальные страницы и бэкенд не трогаем.
- Новых библиотек нет: Recharts уже есть, анимации — CSS-переходы.

## Главное требование: ничего не теряем

Меняется только вид. Всё, что есть на дашборде сейчас, должно остаться и работать так же
(сверено с `pages/Dashboard.tsx` 14.11):

- строка состояния под заголовком (API / база: `common.apiUp`, `common.dbUp`…);
- переключатель периода 30 дней / 90 дней / год;
- пять плиток-метрик с подсказками и «Нет данных»;
- плитки по критичности (пять уровней, цвета из `useSeverityColors`);
- блок «По статусу»;
- график «Появились и закрыты по неделям» с подписью «Неделя с …»;
- блок «Просрочено по командам», включая «Просроченных уязвимостей нет» и команду «без команды»;
- состояния загрузки у каждого блока;
- данные по-прежнему через generic-агрегаты (`aggregate`), ничего не хардкодим под график.

Приёмка: по этому списку пройтись глазами в новой версии — каждого пункта должно быть видно.

## Как выглядит (сверху вниз)

1. **Шапка**: заголовок слева; справа выбор проекта и период «30 дней / 90 дней / год»
   сегментированным переключателем (активный — `--accent-bg` + `--accent`).
2. **Ряд карточек-метрик** (сетка `auto-fit`, на широком экране в один ряд). Карточка:
   подпись, крупная цифра шрифтом `--font-display`, плашка изменения в правом верхнем углу,
   жирная строка-вывод, приглушённая подсказка.
   - «Открыто» — плашка: появилось минус закрыто за период (из недельного ряда, он уже грузится).
   - «Просрочено» — цифра цветом `--sev-critical`, плашка с иконкой.
   - «В срок», «Среднее время исправления», «Согласие с ИИ» — как сейчас, в новом виде.
   - «По критичности» — одна карточка со списком (цвет + текст + иконка) вместо ряда из пяти плиток.
3. **Большой график** «Появились и закрыты по неделям»: области с полупрозрачной заливкой
   вместо столбцов, легенда в шапке карточки.
4. **Две колонки**: «Просрочено по командам» и «По статусу» — горизонтальные полосы.
5. **Таблица** «Последние уязвимости» на всю ширину.

Карточки: скругление 10px, отступы 14–16px, расстояние между карточками 12px.

## План

1. Общие стили карточки-метрики, плашки и сегментированного переключателя — `theme/global.css`.
2. `MetricTile` в новом виде + плашка изменения для «Открыто» — `pages/Dashboard.tsx`.
3. Шапка: период сегментированным переключателем — `pages/Dashboard.tsx`.
4. Карточка «По критичности» вместо ряда плиток (переходы в список, если они есть, сохранить) — `pages/Dashboard.tsx`.
5. График: `AreaChart` вместо `BarChart`, цвета из переменных темы — `pages/Dashboard.tsx`.
6. Нижние блоки в две колонки, таблица на всю ширину — `pages/Dashboard.tsx`.
7. Новые строки (выводы в карточках) — `i18n/ru.json`.
9. Выбор проекта в шапке («Все проекты» по умолчанию): фильтрует все блоки, видны только доступные пользователю проекты — `pages/Dashboard.tsx`.
10. Таблица «Последние уязвимости» (номер SV-N, название, критичность, проект; строка открывает окно SV-N) — `pages/Dashboard.tsx`.
8. Проверка во всех пяти темах и на узком экране; поправить UI-тест дашборда, если ищет старую разметку — `e2e/*.spec.ts`.

## Открытое

  и таблица «Последние уязвимости» (шаги 9–10). На дашборде их сейчас нет, строки
  `dashboard.allProducts` и `dashboard.recent` в `ru.json` уже лежат.
  Перед началом проверить в API (не проверялось): принимает ли `POST /metrics/aggregate`
  фильтр по проекту с поддеревом и чем отдать последние находки (список `findings` с сортировкой
  по дате). Если чего-то не хватает — сказать пользователю до правок бэкенда, молча не расширять.

- Плашки изменения для «Среднее время исправления» и «Согласие с ИИ» требуют значения за
  предыдущий период. Проверить, умеет ли `POST /metrics/aggregate` сдвинутый период;
  если нет — в этой задаче оставить без плашек, бэкенд не расширять.
- «Просрочено» и «В срок» — значения «сейчас», истории нет, плашки изменения у них не будет.
- Цифры в макете условные.
