# Этап 10 «Обогащение» — спека

Утверждено в обсуждении 21.11.2026. Идея — `docs/proposals/2026-09-19-ai-knowledge-hub.md`, «L1. Обогащение без ИИ».

## Цель

Приклеить к находке внешние данные о реальной опасности: EPSS (вероятность эксплуатации), CISA KEV
(эксплуатируется в атаках), БДУ ФСТЭК (номер в российской базе), CWE (название и категория). Дать фильтры,
сортировку и плитку на дашборде, передать данные ИИ и агентам.

## Принятые решения

- **Закрытый контур**: воркер в интернет не ходит. Файлы справочников администратор загружает через админку
  (страница «Справочники»). Автоскачивания нет.
- **Все четыре справочника** в первой версии: EPSS, KEV, БДУ, CWE.
- **Только показ + ИИ**. Влияния на SLA и severity нет (отдельный шаг потом).
- **Хранение — гибрид**: полные данные в таблицах справочников (читаются при открытии SV-N), в находку
  копируются только сводные поля для списка; их пересчитывает воркер при импорте и после загрузки справочника.
- **Право `intel:manage`** («Управление справочниками») — в `GLOBAL_ONLY`: справочник один на систему, в привязке
  к проекту право игнорируется. Видеть обогащение может каждый, кто видит находку (отдельного права нет).

## Данные (миграция 0021)

Каждая загрузка **целиком заменяет** таблицу своего источника (файлы — полные снимки).

| Таблица | Поля |
|---|---|
| `intel_epss` | `cve_id` PK, `epss` (0–1), `percentile` (0–1), `score_date` |
| `intel_kev` | `cve_id` PK, `date_added`, `name`, `ransomware` (bool), `due_date` |
| `intel_bdu` | `bdu_id` PK (`BDU:2021-05969`), `name`, `severity` (текст ФСТЭК) |
| `intel_bdu_cve` | `bdu_id`, `cve_id` (PK пара, индекс по `cve_id`) |
| `intel_cwe` | `cwe_id` PK (`CWE-89`), `name`, `category` |
| `intel_sources` | `source` PK (enum `epss/kev/bdu/cwe`), `status` (`idle/loading/ok/failed`), `loaded_at`, `loaded_by`, `file_date`, `record_count`, `error` |

Категория CWE — из представления MITRE 1400 «Comprehensive Categorization» (покрывает все слабости).
Готовый файл CWE лежит в репозитории (`backend/app/services/intel/data/`) и загружается при первом запуске
(миграция/`seed`), обновить можно через админку.

**Поля находки**: `cves text[]` (GIN), `epss_max float` (индекс), `kev bool` (индекс), `has_bdu bool`.

**Извлечение CVE** (`services/sarif/parser.py`): шаблон `CVE-\d{4}-\d{4,}` (без учёта регистра, приводим к
верхнему) в `ruleId`, `rule.id`, тегах и свойствах правила, свойствах result. Без дублей, по порядку. `GHSA-…`
без CVE не разрешаем. Старые находки получают `cves` командой `python -m app.cli backfill-intel`: та же функция
извлечения по `raw` + пересчёт сводных полей (запускается руками один раз после миграции, идемпотентна).

## Загрузка и пересчёт

Форматы — как отдаёт источник:

| Справочник | Файл |
|---|---|
| EPSS | `epss_scores-YYYY-MM-DD.csv(.gz)`: строка-комментарий `#model_version…,score_date…`, затем `cve,epss,percentile` |
| KEV | `known_exploited_vulnerabilities.json`: `catalogVersion`, `dateReleased`, `vulnerabilities[]` (`cveID`, `dateAdded`, `vulnerabilityName`, `knownRansomwareCampaignUse`, `dueDate`) |
| БДУ | `vulxml.zip` или `export.xml` (XML; XLSX не поддерживаем) |
| CWE | `cwec_v4.x.xml(.zip)` |

Поток:
1. `POST /api/v1/intel/{source}` (multipart, право `intel:manage`): проверка расширения и размера
   (`SV_INTEL_MAX_MB`, по умолчанию 1024), файл — в хранилище (`services/storage.py`), `intel_sources.status =
   loading`, задача ARQ `load_intel`. Если источник уже `loading` — 409 «Загрузка уже идёт». Ответ 202.
2. `load_intel`: потоковый разбор (`csv` по строкам, `iterparse` для XML), проверка формата (нужные колонки/теги,
   хотя бы одна запись). Замена таблицы в одной транзакции (delete + batch insert/COPY).
   Ошибка → старые данные остаются, `status = failed`, `error` — понятный текст.
3. В той же задаче — пересчёт сводных полей у всех находок с непустым `cves` одним `UPDATE … FROM`.
4. `record_audit` (действие `intel.load`): источник, число записей, дата файла. Ошибка тоже пишется.
5. `GET /api/v1/intel` — статус четырёх источников (право `intel:manage`).

При импорте SARIF `apply_import` заполняет `cves` и сводные поля из текущих справочников (новые и обновлённые
находки).

**Устаревание**: EPSS старше 30 дней или KEV старше 7 дней (по `file_date`) — пометка «Данные устарели» на
странице «Справочники» и в окне SV-N. Только подсказка.

## API находок

- `GET /findings/{id}` — блок `intel`: `cwe {id, name, category}`, `cves[] {id, epss, percentile, kev{…}|null,
  bdu[] {id, name, severity}}`, `stale` (какие источники устарели), даты источников.
- Список: поля `epss_max`, `kev`; фильтры `kev`, `min_epss`, `has_bdu`, `cwe_category`; сортировка `epss_max`.
- Метрики/дашборд: `group_by: cwe_category`, фильтр `kev` в generic-агрегатах.

## Интерфейс

- **SV-N, блок «Угрозы»** (если есть CVE или CWE): CWE с названием, категорией и ссылкой на MITRE; по каждому CVE —
  EPSS % и перцентиль, плашка «Эксплуатируется (KEV)» с датой и «вымогатели», БДУ и уровень ФСТЭК; даты и
  «Данные устарели».
- **«Уязвимости»**: колонки «EPSS», «KEV» (значок), фильтры «Только KEV», «EPSS от N%», «Есть в БДУ», «Категория CWE»,
  сортировка по EPSS.
- **Дашборд**: плитка «Открытых в KEV» → переход в отфильтрованный список.
- **`/intel` «Справочники»** (пункт сайдбара только с `intel:manage`): четыре карточки — дата файла, записей,
  статус/ошибка, «Загрузить файл»; пока `loading` — опрос статуса.
- Все строки — в `ru.json`; цвета — из переменных темы.

## ИИ и агенты

- Промпт `triage-v4`: CWE с названием, EPSS, KEV, БДУ — в отдельном блоке «справочные данные» (не в инструкциях).
  Публичные данные, маскирование не нужно.
- MCP: `get_finding` отдаёт блок `intel`; `search_findings` — фильтры `kev`, `min_epss`.

## Тесты

- pytest: парсеры на маленьких фикстурах всех четырёх форматов (включая битые и чужой формат); извлечение CVE
  из SARIF Trivy и Grype; замена таблицы и откат при ошибке; пересчёт сводных полей; 409 при параллельной
  загрузке; право `intel:manage` (403 без него, привязка на проект не даёт); фильтры и сортировка списка; аудит;
  блок `intel` в SV-N и MCP.
- e2e: загрузка KEV-фикстуры → плашка у находки → фильтр «Только KEV» её показывает.

## Вне этапа

Влияние на SLA/приоритет, GHSA без CVE, XLSX для БДУ, автоскачивание из интернета, перевод названий CWE.
